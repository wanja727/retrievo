# 디자인 규칙

Retrievo 화면을 만들거나 고칠 때 지키는 규칙이다. 사람과 에이전트(디자인 스킬 포함) 모두 이 문서를 따른다.
여기 적힌 것은 프로젝트가 일부러 고른 결정이다. 일반적인 디자인 조언과 다르더라도 이 문서가 이긴다.

색과 모양의 실제 값은 `frontend/src/app/globals.css`(노션 ADR-023)에 있다. 값을 바꾸면 이 문서도 함께 고친다.

## 방향

**라벤더가 주인공인, 밝고 깔끔하고 세련된 화면.**

- 흰 바탕이 기본이다. 색은 적게 쓰고, 쓸 때는 이유가 있다
- 라벤더가 테마 색이다. 다른 파스텔 색(민트, 산호)은 맞고 틀림의 판정에만 쓴다 (2026-11-28 결정)
- 장식보다 여백과 정렬로 정돈된 느낌을 낸다
- 웹페이지가 아니라 앱처럼 느껴져야 한다. 누르면 반응하고, 바뀌는 것은 움직임으로 알려 준다
- 모든 요소에는 이유가 있어야 한다. 왜 있는지 말할 수 없는 요소는 뺀다

## 색

| 토큰 | 역할 | 쓰지 않는 곳 |
|---|---|---|
| `accent` 라벤더 (`#8477e6`) | 누를 수 있는 것, 고른 것, 진행, 통과한 확인, 장기 기억 | 장식, 판정 결과 |
| `accent-solid` (`#7064d4`), `accent-solid-press` | 흰 글자를 얹는 라벤더 면(주 버튼)과 누른 상태. `accent` 위 흰 글자는 대비가 모자라다 | 글자 없는 장식 |
| `memory-1`, `memory-2` | 기억 지도와 꺼낸 날 칸의 단계 (`surface` → `memory-1` → `memory-2` → `accent` → `accent-ink`) | 단계가 아닌 곳 |
| `accent-soft`, `accent-line` | 대표 숫자 면(`.hero`), 고른 보기의 바탕과 선 | 넓은 배경 전체 |
| `ok` 민트 | "맞았어요" 판정에만 | 성공 알림, 진행 표시 |
| `wrong` 산호 | "틀렸어요" 판정에만 | 경고, 삭제 같은 일반 위험 표시 |
| `ink` ~ `soft` | 글자. 보랏빛이 도는 짙은 회색. 흰 바탕과 `accent-soft` 위에서 모두 4.5:1을 넘는다 | 순수한 검정(`#000`) |
| `faint` | 자리 표시, 비활성, 장식 아이콘 | 읽어야 하는 글자 (대비 2.4:1) |
| `line`, `line-strong`, `surface` | 나누는 선, 누르는 동안의 바탕 | |

- 판정 색(민트, 산호)은 다른 뜻으로 쓰지 않는다. 사용자가 색만 보고 맞고 틀림을 알기 때문이다
- 색만으로 뜻을 전하지 않는다. 판정에는 글자나 아이콘이 함께 있다
- 글자는 바탕과 4.5:1 이상, 아이콘과 선처럼 뜻이 있는 그림은 3:1 이상이다 (WCAG 2.2 AA). 새 색을 정할 때 계산한다
- 과정이나 주제를 색으로 나누지 않는다. 화면이 다채로워지는 대신 판정 색과 헷갈리고 깔끔함을 잃는다. 구분이 필요하면 글자와 배치로 한다
- 새 색이 필요하면 토큰을 먼저 정하고 이 표에 역할을 적는다. 컴포넌트에 색 값을 바로 쓰지 않는다

## 면과 선

- 흰 바탕에 가는 선(1px)으로 나눈다. 묶음은 `.card`, 작은 면은 `.tile`
- 그림자와 그라데이션은 금지가 아니다. 완성도 있게 쓰면 좋다. 전에 뺀 것은 어설프게 써서 "흔한 AI 디자인"으로 보였기 때문이다 (2026-11-28 사용자가 바로잡음)
  - 쓸 때는 이유가 있어야 한다: 그림자는 실제로 떠 있는 것(시트, 눌리는 카드)에, 그라데이션은 강조할 한 곳에. 모든 카드에 똑같이 깔지 않는다
  - 지금 화면은 그림자 없이 선으로 나누고, 그라데이션은 `.celebrate`(라벤더가 위에서 흰색으로 옅어짐)만 쓴다. 바꿀 때는 후보를 그려 사용자가 고른다
- 반투명, 번짐(blur), 글래스모피즘은 배경이 산만해져서 뺐다
- 모서리: 카드 20px, 대표 숫자 면 28px. 안에 든 면은 바깥보다 작게 한다
- 채운 원 안의 체크 같은 아이콘은 써도 된다. 선이 원에 비해 가늘면 어색하다. 선을 두껍게 고칠 때는 선 두께만 바꾸고 원과 아이콘의 크기는 그대로 둔다 (전에 두께를 고쳐 달라는 말에 원까지 키운 적이 있다)
- 고쳐 달라는 것만 고친다. 하나를 고치면서 크기, 간격, 색 같은 다른 값을 함께 바꾸지 않는다

## 글자

- 숫자와 영문은 Inter Tight, 한글은 Noto Sans KR, 코드는 JetBrains Mono (ADR-018)
- 한글은 단어 중간에서 줄을 바꾸지 않는다 (`word-break: keep-all`, `body`에 걸려 있다)
- 화면의 글은 해요체로 쓴다. 영어 UI의 규칙(대소문자, 둥근 따옴표, 동사로 시작하는 버튼)은 적용하지 않는다
- 가운뎃점(·)으로 정보를 늘어놓지 않는다

## 움직임

- 과하지 않은 움직임은 완성도를 높인다. 너무 정적이면 앱이 아니라 웹페이지처럼 보인다 (2026-11-28 사용자 의견). 오늘 화면에는 숫자가 올라가는 것(`useCountUp`), 막대와 고리가 차는 것(`.grow-x`, `.grow-y`, `.ring-draw`), 끝낸 일의 체크(`.pop`), 누를 때의 반응이 있다. 다른 화면은 아직 `.fade-up`(240ms)뿐이다
- 움직임을 넣기 좋은 곳: 누를 때의 반응, 정답과 오답의 판정, 숫자가 올라가는 순간, 진행 막대가 차는 것, 화면과 시트의 전환
- 움직임에는 이유가 있어야 한다: 무엇이 바뀌었는지, 어디서 왔는지를 알려 준다. 장식으로만 움직이지 않는다
- 하루에 수십 번 보는 것(보기 누르기 등)은 짧게(150ms 안팎), 가끔 보는 것(졸업, 다 마친 화면)은 더 풍부하게 한다
- `prefers-reduced-motion`을 켠 사용자에게는 움직이지 않는다

## 쓰지 않는 것

같은 지적을 다시 받지 않으려고 적는다. 디자인을 세 번 다시 만들며 나온 것이다.

- 이유 없이 모든 카드에 깔린 그림자, 떠 있는 하단 바 (그림자 자체는 금지가 아니다. "면과 선" 참고)
- 여러 색을 섞은 그라데이션, 그라데이션 글자와 버튼을 어설프게 쓴 것
- 글래스모피즘, 반투명 면
- 노란 상자 강조, 아이보리 바탕
- 강한 파랑, 탁한 초록, 강한 빨강
- 시스템이 관리하는 숫자(확인 2/4 같은 것)를 사용자에게 보여 주는 것

## 화면에서 중요하게 보는 것

- 쓸수록 성장한다고 느끼게 한다. 메인 화면은 위에서 아래로 시간 범위가 넓어진다: 인사, 오늘 할 일, 연속 학습, 이번 주, 최근 기억률, 전체 로드맵, 과정별 진행도 (2026-11-28 다시 설계)
- 숫자를 늘어놓지 않고 그림(고리, 막대)으로 보여 준다. 숫자만 있는 값(꺼낸 횟수 같은 것)은 메인 화면에 두지 않는다
- 메인 화면의 값은 늘어나기만 하는 값이 기본이다. 예외는 최근 기억률 하나다: 내려갈 수 있지만 최근 30일 값이라 복습하면 회복되고, 내려가는 값이 있어야 복습할 이유가 생긴다. 표본이 5번보다 적으면 숫자 대신 안내를 보여 준다. 그 밖의 비율(정답률)은 기록 화면에만 둔다
- 오늘 할 일은 복습과 새 레슨 1개다. 어떤 레슨을 배울지는 사용자가 고르고, 앱이 정해 주지 않는다
- 앱은 모바일 웹이다. 넓은 화면에서는 가운데 430px 폭으로만 보여 준다
- 320px 너비에서도 잘리거나 겹치지 않는다
